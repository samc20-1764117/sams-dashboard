# Pages Rules

### Overview (`overview.js`)
- **Shared week offset**: weekly calendar (`wkOff`) and Weekly Reset card (`wrRecOff`) are kept in lockstep — `shiftWk`/`shiftWrRec`/`goThisWk`/the "This Week" buttons all route through `_goToWeek(off)` which sets BOTH offsets and re-renders weekly cal + summary + unassigned + pup highlight + meal row + `renderRecOv()` + the videos pop-up (if open). `shiftDay`/`goToday` also sync `wrRecOff` when day-nav crosses a week. Do NOT set `wkOff`/`wrRecOff` directly for navigation — use `_goToWeek`.
- **Today list** sort: done last→travel→overdue→important→type (regular=1,rec=2,shop=3,bday=4)→name. `_hasTBToday` checks `st.blocks` (by `ruleId/shopId/recId/taskId/_vidId`) AND `getRecAutoTBForDate` (by `_recId`) for recurring tasks with `default_start_time`. Overdue pup sessions (`day_date < today && !done`) appear in today list when `dayOff===0` via `isOv(s.day_date)` filter.
- **Videos on today list**: shown via `vidToday` filter — videos in day map (`_vidDayMap`) or on a timeblock (`_vidOnTBToday`). Published videos show as checked/greyed (`.done` class). `tRowVidVirt` renders with `${t.done?'done':''}` class and checked checkbox.
- **Published/done videos do NOT use the day map for display or auto-move** (both `vidToday` and weekly-cal `vidForDay` gate the `_vidDayMap[id]===ds` check with `v.status!=='published'`): the overdue-auto-move (`renderToday` step 1) and block-cleanup (step 2) both skip published videos, so a finished video stays on the day it was done instead of being dragged onto today as a crossed-out duplicate. A done video appears via its TB block or, while its big/small group is still incomplete (`_vidStillPending`/`_vPend` = published && !`_vidGroupFullyComplete`), on its `post_date` day only (NOT as overdue on today).
- **WR tasks in today list**: appear if `_dateOverrides[wkKey]===today` OR overdue (4-week lookback, undone only). `wrRulesToday/wrecToday` use seen sets to dedup. **Dedup key is `ruleId::wkKey`** (not just `ruleId`) — allows the same rule to appear for multiple weeks (e.g., HEB moved from last Sunday + this Sunday's natural instance).
- **Shopping overview** (`#shopOv`): NO rAF-based max-height — caused items to be hidden when `offsetHeight=0` during background sync. Height naturally constrained by card's `overflow:hidden` + flex. Sort (`_shopOvSort`): `shop_order` alone, unconditionally — `due_date` is metadata shown on the row, not a sort key (deliberate; it used to sort due-date items first, which silently blocked Cmd+↑/↓ from moving an item past a differently-dated neighbor — reverted). Drag-to-calendar assigns `_shopTopOrder` (min `shop_order` - 1). **Weekly cal chips**: store name NOT shown in parentheses.
- **WR overview list** (`#recList`): `columns:2;column-fill:auto`. `max-height = 4 + 7 * itemHeight` (set in rAF, exactly 7 rows per column).
- **Pup Skills Highlight** (`#pupSkillsHighlight`): below `#todList`. Two side-by-side inset tiles (Mochi / Sunny) showing this week's focus skills. Weekly focus tracked via `pup_weekly_focus` Supabase table (`skill_id uuid`, `week_start`). Auto-seeded from `pup_skills.focus` flag via `seedPupWeeklyFocus()` (guarded by `_pupWkFocusSeeding`). Each tile: flex column, `border-radius:12px`, inset white container. Undone skills sorted to top, done-this-week to bottom (opacity `.35`, no strikethrough). Progress bar: `rgba(16,185,129,.7)`, pinned to bottom via flex spacer `<div style="flex:1">`. Counts use `tabular-nums`. Hover tooltip shows total sessions. Tiles hidden when no focus skills for either pup. Checkbox syncs via `togPupSkillTrained`; time block pup checkbox uses `b.cat==='pup_session'&&b._pupSessId` branch.
  - **Per-tile hide/show** (persisted in `localStorage._pupHiddenTiles` JSON array): each tile header has a hover-reveal eye-off button (`.pup-tile-hide`, opacity 0 → `.pup-tile:hover` reveals) → `_setPupTileHidden(pup,true)`. A hidden pup collapses to a slim dashed restore chip (`.pup-restore-chip`, vertical name + eye icon) → click `_setPupTileHidden(pup,false)`. No always-visible hide button. The donut (`#todProgressDonut`) is a separate centered row above and just reflows — it is NOT repositioned when tiles hide.
- **Layout**: `.row1-right-top` uses `height:min(225px,28vh)` (not max-height) to prevent container resizing when navigating weeks.
- **`.overview-cols` height** (fixed 2026-08-23): must stay `calc(100vh - 84px)` with NO `min(Npx, ...)` cap — a `min(740px, calc(100vh - 84px))` cap previously froze the whole two-column layout at 740px tall on any window taller than ~824px, leaving a large blank strip below both columns on fullscreen/large displays even though the columns' own contents (`#todList`, `.wkc-*`) are already `flex:1` and would correctly fill more space if given it. Don't reintroduce a px cap here. Separately, `#mModal`'s month-grid item-truncation counts (`_gCellH`/`_cellH` in `renderMoCal()`, features.js) are computed from `window.innerHeight` only at render time with no resize handling — a debounced `window.resize` listener (~features.js:5992) now calls `renderMoCal()` to keep that in sync too.

### Finance (`features.js`)
- **Layout**: 2-column `fin-layout`. Left: Personal Finances card + Investments card. Right: Recurring Expenses card (or Purchase History panel when details open).
- **Investments quick-add**: `+` opens inline dropdown under button (not a modal). Date defaults to today. Enter in amount field submits.
- **Purchase History panel**: `Details` button toggles `_finDetailsOpen`, replaces right column with scrollable purchase table + `+` button. Close `x` returns to Recurring Expenses.
- **Subscriptions**: inline contenteditable editing. Tab moves to next field in same row (name → freq `<select>` → due day → amount), via `_finSubTabNext` walking `[contenteditable="true"],select.fin-freq-sel` sorted by x-position. New sub via `+` (or double-click empty space in the card) focuses name field with `_unsaved:true`; only POSTs when name is non-empty on blur. Clicking away or Escape with empty name cancels (removes row). Only required field: name.
  - **Gotcha — async commit vs `<select>` focus restore**: committing a new row (`_finCommitNew`) swaps the row's local `l-...` id for the real one *after* the POST resolves, then re-renders and tries to restore focus/text onto whatever field was active. If that field is the freq `<select>` (user tabbed straight into it), never do `el.textContent = editText` on it — a `<select>`'s `textContent` includes all its `<option>` labels concatenated, and assigning it wipes out the `<option>` elements entirely, silently breaking the dropdown. Check `el.tagName==='SELECT'` and just `.focus()` it instead. Same class of bug hit `_finSubEditFreq`: changing frequency on an already-saved row calls `renderFinancePage()` synchronously, which drops focus to `body` — re-`.focus()` the freshly-rendered `<select>` by `[data-fid][data-field="frequency"]` right after.
  - **Gotcha — margin vs transform in a `table-layout:fixed` column**: `.fin-col-del`/`td:last-child` is a fixed 24px column; a `margin-right` on `.delbtn` inside it is silently ignored (box-model width solving under `table-layout:fixed` clamps it away) even though the computed style reports the value. Use `transform:translateX(-Npx)` instead — it isn't part of layout and reliably shifts the element. If a nudge/offset on an element inside a fixed-width table cell "isn't taking effect" despite correct CSS, suspect this before anything else.
- **Double-click-to-add**: Recurring Expenses, Personal Finances (accounts), and Investments cards all support double-clicking empty space to add a row (`addFinSub()` / `addFinRow('account')` / `openFinInvAdd(event)`), guarded via `event.target.closest(...)` so it doesn't fire on rows/buttons/the donut/chart-dot hit-targets.
  - **Gotcha**: on Investments, `.fin-chart-dot-hit` (the area-chart hover tooltip's hit target) used to be `height:100%`, tiling the *entire* chart area with no true empty space left for the double-click guard to ever pass through. Shrunk to `height:70%;top:15%` (styles.css) so the hover zone stays generous while the top/bottom 15% strips stay double-clickable. If a double-click-to-add ever "does nothing" on a card with hover-tracking elements, check for a full-height/full-width hit-target absorbing the whole area first.
- **Fin-cancel tasks**: checking off on overview archives the subscription and marks done visually. Undo restores both. `_finCancelTasksForDate` includes archived subs in `_finCancelDone` set.
- **Keyboard shortcuts**: global shortcuts (`s`, `n`, `r`) do NOT fire when typing in contenteditable/input/textarea fields. `s` (grocery modal) is overview-only.
- **Points & Flight Credits** (`fin_points` table): opened via the → icon next to the "Points & Credits" legend row, or by double-clicking that legend row itself. Popup mirrors Purchase History's UX (double-click-to-add, tab-to-next-field, tab-past-last-field-of-last-row adds a new row). Table columns: Name, Amount+unit (`$`/`mi`/`pts` via `.fin-pts-unit-sel`), Expires, Remind (days-before, `remind_days_before`), Reminds On (read-only, computed via `_finPtsReminderDate(expires_on, remind_days_before)` — updates live as either input changes, not stored), $ Value. The Personal Finances legend's dollar total for this row = `_finPtsTotal()`, summing every entry with miles/points converted at a flat `_FIN_PTS_RATE=0.01`/unit. Expiration reminder is a single-occurrence virtual task injected by `_finCancelTasksForDate` on the exact date `expires_on − remind_days_before`, with `important:true` set explicitly (don't rely only on `_type==='fin-cancel'` — some views like mobile only check `t.important`).
  - **Gotcha — `sort_order` must be unique/incrementing, never a shared constant**: every new row in `fin_points`/`finance`/`finance_subs` needs a real incrementing `sort_order` (e.g. `max(existing)+1`), not a hardcoded `0`. Server fetches order by `expires_on.asc.nullslast,sort_order.asc.nullslast` (or the equivalent per table) — if a whole batch of rows ties on both keys, Postgres has no stable secondary sort and can return them in a different physical order after any `UPDATE` (MVCC rewrites the row), which looks like the row "jumped position" right after an edit. Client-side `.sort()` comparators should also fall back to comparing `id` as a final tiebreaker so render order stays 100% deterministic regardless of what order the server hands back, independent of whether `sort_order` is fixed.
  - **Gotcha — never refresh/re-render synchronously when a changed field saves**: an existing row's field-save function (`_finPointsSave`, `_finPHSave`, etc.) must NOT call `_finPointsRefresh()`/`renderFinancePage()` immediately when the value actually changed — that rebuilds the row's DOM out from under a `.focus()` call already in flight from Tab (moving to the next field triggers this field's `blur` synchronously), killing the tab chain and dropping focus onto an unrelated element elsewhere on the page. Defer the render via `setTimeout(finishIfDone,0)` unconditionally. `finishIfDone`'s "am I still editing" check must scan the *whole popup* for any row with the editing class (`document.activeElement.closest('#pop tr.fin-ph-editing')`), not just this row's own `tr` — tabbing off the last field of a row moves focus into the NEXT row (already re-entered edit mode) before this row's own deferred check runs, and checking only its own `tr` refreshes the whole popup and wipes the next row's fresh edit-mode DOM too.
  - **Gotcha — a "—"/empty display placeholder is not "invalid user input"**: a null date field shows `_finPHDateDisplay(null)` → `"—"` as the text input's value while editing. A date-text save function that treats any unparseable non-empty string as an error (and immediately refreshes) will trip on this literal `"—"` the instant the user tabs through an untouched empty-date row — treat `"—"` as equivalent to empty before attempting to parse.
  - **Gotcha — table-layout:fixed popups need a `min-width` + `overflow-x:auto`, not just fixed column widths**: an `auto`-width leftover column (e.g. Name, after Amount/Expires/Remind/etc. take their declared pixel widths) gets whatever space remains in the *popup's actual width* — if the popup ever renders narrower than the sum of the fixed columns (a smaller browser window; the popup mirrors a sibling card's width), the leftover column can collapse to a few px. Invisible in plain display text (just truncates quietly), but glaring the instant edit mode renders an actual bordered input into that sliver — reads as fields "shifting" on double-click. Fix: `min-width` on the table + `overflow-x:auto` on its scroll container, so it degrades to horizontally scrollable instead of corrupting.
  - **Gotcha — native number-input spinners and `<select>` chevrons don't size predictably in narrow inline-edit cells**: hide spinner arrows (`::-webkit-inner/outer-spin-button{-webkit-appearance:none}` + `-moz-appearance:textfield`) since a typed-in balance never needs them and they eat ~16px unpredictably; give unit `<select>`s an explicit width+font-size (36–42px / 11px minimum) rather than letting them auto-size, or short labels like "mi" can visually compress illegibly.
