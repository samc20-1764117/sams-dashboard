# Pages Rules

### Overview (`overview.js`)
- **Shared week offset**: weekly calendar (`wkOff`) and Weekly Reset card (`wrRecOff`) are kept in lockstep — `shiftWk`/`shiftWrRec`/`goThisWk`/the "This Week" buttons all route through `_goToWeek(off)` which sets BOTH offsets and re-renders weekly cal + summary + unassigned + pup highlight + meal row + `renderRecOv()` + the videos pop-up (if open). `shiftDay`/`goToday` also sync `wrRecOff` when day-nav crosses a week. Do NOT set `wkOff`/`wrRecOff` directly for navigation — use `_goToWeek`.
- **Today list** sort: done last→travel→overdue→important→type (regular=1,rec=2,shop=3,bday=4)→name. `_hasTBToday` checks `st.blocks` (by `ruleId/shopId/recId/taskId/_vidId`) AND `getRecAutoTBForDate` (by `_recId`) for recurring tasks with `default_start_time`. Overdue pup sessions (`day_date < today && !done`) appear in today list when `dayOff===0` via `isOv(s.day_date)` filter.
- **Videos on today list**: shown via `vidToday` filter — videos in day map (`_vidDayMap`) or on a timeblock (`_vidOnTBToday`). Published videos show as checked/greyed (`.done` class). `tRowVidVirt` renders with `${t.done?'done':''}` class and checked checkbox.
- **Published/done videos do NOT use the day map for display or auto-move** (both `vidToday` and weekly-cal `vidForDay` gate the `_vidDayMap[id]===ds` check with `v.status!=='published'`): the overdue-auto-move (`renderToday` step 1) and block-cleanup (step 2) both skip published videos, so a finished video stays on the day it was done instead of being dragged onto today as a crossed-out duplicate. A done video appears via its TB block or, while its big/small group is still incomplete (`_vidStillPending`/`_vPend` = published && !`_vidGroupFullyComplete`), on its `post_date` day only (NOT as overdue on today).
- **WR tasks in today list**: appear if `_dateOverrides[wkKey]===today` OR overdue (4-week lookback, undone only). `wrRulesToday/wrecToday` use seen sets to dedup. **Dedup key is `ruleId::wkKey`** (not just `ruleId`) — allows the same rule to appear for multiple weeks (e.g., HEB moved from last Sunday + this Sunday's natural instance).
- **Shopping overview** (`#shopOv`): NO rAF-based max-height — caused items to be hidden when `offsetHeight=0` during background sync. Height naturally constrained by card's `overflow:hidden` + flex. **Sort (`_shopOvSort`, 2026-09-14 tiered redesign — explicit user request, supersedes the old "due_date is not a sort key" rule)**: on-calendar items (`due_date` set) always float to the top, soonest date first; everything else sorts by `shop_order` (manual order) below that — a hard boolean tier (on-calendar vs not), not due_date interleaved item-by-item with manual order, which is what caused the earlier revert (see below). `renderShopFull`'s manual mode (features.js) calls the same `_shopOvSort` for its display order and its drag-reorder's no-op comparison, so both shopping surfaces agree. **New items land at the top of the manual tier**, not the bottom: `_shopNewOrder()` (overview.js, top of non-calendar tier = min existing `shop_order` - 1) is used by Quick Add, the full shopping page's add box, AND the Alexa `add to shopping list` intent (`functions/api/alexa.js` — queries `?order=shop_order.asc.nullslast&limit=1` server-side first, same formula) — previously none of the three set `shop_order` at all, so new items defaulted to the `??9999` fallback and sorted near the bottom instead. **Cmd+↑/↓ reorder cannot cross the calendar/manual tier boundary** (`_shopOvKeyNav`, overview.js) — blocked outright (no-op) rather than left to silently snap back on the next render, which is the exact "differently-dated neighbor" bug that caused the 2026-08(ish) revert; a hard tier boundary doesn't have that failure mode since manual order still fully controls position WITHIN each tier. Drag-to-calendar assigns `_shopTopOrder` (min `shop_order` - 1, distinct from `_shopNewOrder` — excludes the item's own id since it already exists in `st.shopping`). **Weekly cal chips**: store name NOT shown in parentheses.
- **WR overview list** (`#recList`): `columns:2;column-fill:auto`. Height is set in an rAF callback from the CARD's actual rendered height minus its other children (not a fixed "N rows" formula) — see `rules/wr-system.md` → "WR overview list" for the exact mechanism and how the floating +/Skip button (`.wr-float-pill`) is excluded from it.

A raw `scrollTop` save/restore doesn't survive this (filtering changes chip counts per-cell, which can change row heights above the current scroll position too). ### Finance (`features.js`)
- **Layout**: 2-column `fin-layout`. Left: Personal Finances card + Investments card. Right: Recurring Expenses card (or Purchase History panel when details open).
- **Investments quick-add**: `+` opens inline dropdown under button (not a modal). Date defaults to today. Enter in amount field submits.
- **Purchase History popup**: `History` button on the Investments card (`openFinInvDetails()`) overlays a `fin-details-pop` popup on the right column with a scrollable purchase table + `+` button; `x` or Escape closes it (`closeFinInvDetails()`). Date and Amount are always-editable `contenteditable` spans (`_finPHEditableDate`/`_finPHEditableAmt`, class `fin-sub-plain`) — click directly into a cell to edit, no separate edit mode. Dates are typed as `MM/DD/YY` text only (no calendar-picker button). Tab via `_finPHTabNext`, save via `_finPHSaveField(id,field,el)`.
- **Subscriptions**: inline contenteditable editing. Tab moves to next field in same row (name → freq `<select>` → due day → amount), via `_finSubTabNext` walking `[contenteditable="true"],select.fin-freq-sel` sorted by x-position. New sub via `+` (or double-click empty space in the card) focuses name field with `_unsaved:true`; only POSTs when name is non-empty on blur. Clicking away or Escape with empty name cancels (removes row). Only required field: name.
  - **Gotcha — async commit vs `<select>` focus restore**: committing a new row (`_finCommitNew`) swaps the row's local `l-...` id for the real one *after* the POST resolves, then re-renders and tries to restore focus/text onto whatever field was active. If that field is the freq `<select>` (user tabbed straight into it), never do `el.textContent = editText` on it — a `<select>`'s `textContent` includes all its `<option>` labels concatenated, and assigning it wipes out the `<option>` elements entirely, silently breaking the dropdown. Check `el.tagName==='SELECT'` and just `.focus()` it instead. Same class of bug hit `_finSubEditFreq`: changing frequency on an already-saved row calls `renderFinancePage()` synchronously, which drops focus to `body` — re-`.focus()` the freshly-rendered `<select>` by `[data-fid][data-field="frequency"]` right after.
  - **Gotcha — margin vs transform in a `table-layout:fixed` column**: `.fin-col-del`/`td:last-child` is a fixed 24px column; a `margin-right` on `.delbtn` inside it is silently ignored (box-model width solving under `table-layout:fixed` clamps it away) even though the computed style reports the value. Use `transform:translateX(-Npx)` instead — it isn't part of layout and reliably shifts the element. If a nudge/offset on an element inside a fixed-width table cell "isn't taking effect" despite correct CSS, suspect this before anything else.
- **Double-click-to-add**: Recurring Expenses, Personal Finances (accounts), and Investments cards all support double-clicking empty space to add a row (`addFinSub()` / `addFinRow('account')` / `openFinInvAdd(event)`), guarded via `event.target.closest(...)` so it doesn't fire on rows/buttons/the donut/chart-dot hit-targets.
  - **Gotcha**: on Investments, `.fin-chart-dot-hit` (the area-chart hover tooltip's hit target) used to be `height:100%`, tiling the *entire* chart area with no true empty space left for the double-click guard to ever pass through. Shrunk to `height:70%;top:15%` (styles.css) so the hover zone stays generous while the top/bottom 15% strips stay double-clickable. If a double-click-to-add ever "does nothing" on a card with hover-tracking elements, check for a full-height/full-width hit-target absorbing the whole area first.
- **Fin-cancel tasks**: checking off on overview archives the subscription and marks done visually. Undo restores both. `_finCancelTasksForDate` includes archived subs in `_finCancelDone` set.
- **Keyboard shortcuts**: global shortcuts (`s`, `n`, `r`) do NOT fire when typing in contenteditable/input/textarea fields. `s` (grocery modal) is overview-only.
- **Points & Flight Credits** (`fin_points` table): opened via the → icon next to the "Points & Credits" legend row, or by double-clicking that legend row itself (`openFinPointsDetails()`). **Always-editable, contenteditable-based** (`_finRenderPointsContent`, features.js ~L3458) — same pattern as Recurring Expenses' `_finSubEditable`, not a double-click-to-enter-edit-mode swap. Table columns: Name, Amount (plain number, `_finPtsEditableAmt`), **Unit — its own dedicated `<select>` column** (`_finPtsUnitSelect`, reuses `.fin-freq-sel` styling, saved via `_finPointsSaveUnit`), Expires (typed `MM/DD/YY` text, no calendar picker), Remind (days-before, `remind_days_before` — **optional**, clear it for no reminder, same "—" convention as Expires), Reminds On (read-only, computed via `_finPtsReminderDate(expires_on, remind_days_before)` — returns `null`/"—" if either input is unset, not stored), $ Value. Save goes through one `_finPointsSaveField(id,field,el)` for the contenteditable fields. Tab-chain (`_finPointsTabNext`) re-locates the next field by `data-fid`/`data-field` after a `setTimeout(...,30)`, never a stale element reference — same pattern in Purchase History's `_finPHTabNext` and Recurring's `_finSubTabNext`. The Personal Finances legend's dollar total for this row = `_finPtsTotal()`, summing every entry with miles/points converted at a flat `_FIN_PTS_RATE=0.01`/unit. Expiration reminder is a single-occurrence virtual task injected by `_finCancelTasksForDate` on the exact date `expires_on − remind_days_before` — skipped entirely (no task, not even a 90-day-default one) if either `expires_on` or `remind_days_before` is unset; `important:true` set explicitly (don't rely only on `_type==='fin-cancel'` — some views like mobile only check `t.important`).
  - **Why not a double-click-edit-mode toggle (history, 2026-09-05)**: the original design swapped a row's plain-text cells into bordered `<input>`/`<select>` elements on double-click and back on blur (`_finPointsEdit`/`_finPHEdit`, `tr.classList.add('fin-ph-editing')`). Ten separate rounds of "fields shift/misalign" bugs all traced back to some way the swapped-in edit DOM didn't line up with, or briefly behaved differently from, the plain-text DOM it replaced. Rebuilt on Recurring's always-editable-span pattern instead, which structurally can't have this bug class — the display element and the edit element are the same node, always.
  - **Gotcha — `sort_order` must be unique/incrementing, never a shared constant**: every new row in `fin_points`/`finance`/`finance_subs` needs a real incrementing `sort_order` (e.g. `max(existing)+1`), not a hardcoded `0`. Server fetches order by `expires_on.asc.nullslast,sort_order.asc.nullslast` (or the equivalent per table) — if a whole batch of rows ties on both keys, Postgres has no stable secondary sort and can return them in a different physical order after any `UPDATE` (MVCC rewrites the row), which looks like the row "jumped position" right after an edit. Client-side `.sort()` comparators should also fall back to comparing `id` as a final tiebreaker so render order stays 100% deterministic regardless of what order the server hands back, independent of whether `sort_order` is fixed.
  - **Gotcha — a "—"/empty display placeholder is not "invalid user input"**: applies to both Expires and Remind now. A cleared date field shows `_finPHDateDisplay(null)` → `"—"`; a cleared Remind field shows `"—"` too. A save function that treats any unparseable non-empty string as an error (and immediately refreshes) will trip on the literal `"—"` the instant the user tabs through an untouched empty field — treat `"—"`/empty as "clear this field to null", not as invalid typed text.
  - **Gotcha — a popup's Escape/Enter-to-close `keydown` listener must also check `e.target.isContentEditable`**, not just `tagName==='INPUT'/'TEXTAREA'/'SELECT'`: `openFinPointsDetails()`/`openFinInvDetails()` both attach a document-level listener that closes the popup on Enter/Escape unless focus is in a form field. A `contenteditable` span's own `onkeydown` calling `preventDefault()` does **not** stop the event from bubbling to that listener — without the `isContentEditable` check, hitting Enter to save a field closed the whole popup instead (real bug, fixed 2026-09-05).
  - **Gotcha — table-layout:fixed popups need a `min-width` + `overflow-x:auto`, not just fixed column widths**: an `auto`-width leftover column (e.g. Name) gets whatever space remains in the *popup's actual width* — if the popup ever renders narrower than the sum of the fixed columns (a smaller browser window), the leftover column can collapse to a few px, truncating long names. Fix: `min-width` on the table (`.fin-pts-tbl{min-width:560px}`) + `overflow-x:auto` on its scroll container, so it degrades to horizontally scrollable instead of corrupting.
